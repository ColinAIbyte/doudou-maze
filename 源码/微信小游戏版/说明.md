# 微信小游戏版（源码，供阅读）

这是《豆豆迷宫》的微信小游戏外壳。**游戏逻辑不在这里** —— `js/core.js` 是
从 `源码/pacman_fragment.html`（网页版）机械生成的，不要手改。

```
game.js        入口：建画布、装垫片、起游戏、输入、合成循环、微信接口
js/shim.js     垫片：把核心要用的那一小片 DOM / localStorage / rAF 补出来
js/ui.js       界面：HUD、弹层、说明页、开始页，全部画在 canvas 上
js/core.js     ← 自动生成，改网页版再跑 工具/build_weapp.mjs
工具/smoke.mjs  无头冒烟测试：node 工具/smoke.mjs
```

## 为什么要有垫片

核心逻辑是给浏览器写的，会用 `document.getElementById`、`localStorage`、
全局 `requestAnimationFrame`。小游戏里这些要么没有、要么形状不同（rAF 挂在
canvas 节点上而不是全局；新版基础库里 `window`/`document` 是**只读 getter**，
直接赋值会抛异常）。垫片负责把这层差异吸收掉，核心一行都不用改。

## 已知的坑（都踩过，注释里写了原委）

- 给 canvas 赋 `width` 会**连带清空 ctx 的变换**，而核心加载时会重设一次画布
  尺寸 —— 所以外壳的分辨率设置必须放在 `createGame()` **之后**
- 垫片造的假元素有 `addEventListener` 却**没有** `dataset`，读一下就抛
- rAF 回调必须包 try/catch：核心那条循环里只要抛一次，`requestAnimationFrame(loop)`
  就执行不到，循环无声断掉、画面定格，不报任何错
- 分享不给 `imageUrl` 的话，微信会拿当前那一帧去截图
